Aplikasi: SEREMIND

0. Nama Aplikasi
Seremind — gabungan dari Serenity (ketenangan) dan Mind (pikiran).

Arti: Pikiran yang tenang.

Tagline: Seremind — Tenang Sebelum Bertindak.

Filosofi nama:

Kami memilih nama Seremind karena kami percaya bahwa akar dari kebiasaan digital yang tidak sehat bukanlah kurangnya disiplin, melainkan kurangnya ketenangan pikiran. Ketika pikiran tenang, kita bisa memilih. Ketika pikiran kacau, kita hanya bereaksi. Seremind hadir untuk menciptakan ruang tenang itu — tepat di momen sebelum kebiasaan otomatis mengambil alih.

1. Latar Belakang & Masalah
1.1 Konteks
Penggunaan smartphone telah menjadi bagian tak terpisahkan dari kehidupan sehari-hari. Namun, pola penggunaan yang didominasi oleh aplikasi dengan stimulasi tinggi — media sosial, video pendek, game — telah menciptakan kebiasaan otomatis yang sulit diinterupsi.

Riset neurosains terbaru dari UCL menemukan bahwa otak memiliki dua sistem pembelajaran dopamin yang bekerja paralel:

Reward Prediction Error (RPE): sinyal yang muncul ketika hasil lebih baik atau lebih buruk dari yang diharapkan.

Action Prediction Error (APE): sinyal yang mengupdate seberapa sering suatu aksi dilakukan, terlepas dari nilainya.

Kebiasaan buruk seperti doomscrolling tidak dikendalikan oleh RPE, melainkan oleh APE. Pengguna tidak scroll karena mengharapkan reward tertentu. Mereka scroll karena aksi itu sudah menjadi default policy — otak telah menghemat resources dengan menjadikannya kebiasaan otomatis.

1.2 Masalah
Aplikasi pemblokir yang ada saat ini mencoba menyerang RPE — dengan memberi reward atau punishment. Padahal yang harus diserang adalah APE. Akibatnya, kebanyakan aplikasi pemblokir gagal karena:

Fokus pada pemblokiran, bukan interupsi kebiasaan

Tidak membantu pengguna memahami mengapa kebiasaan itu terjadi

Menghukum pengguna ketika gagal, bukan membantu mereka pulih

Tidak memberikan jeda reflektif di momen sebelum kebiasaan terjadi

Tidak membantu pengguna memahami hubungan antara emosi dan kebiasaan

1.3 Peluang
Ada celah untuk aplikasi yang:

Menginterupsi kebiasaan otomatis di momen paling kritis — sebelum aksi terjadi

Membantu pengguna menyadari pola pemicu tanpa menghakimi

Memberikan konteks ilmiah mengapa kebiasaan itu sulit diubah

Menyediakan ruang refleksi (jurnal) yang menghubungkan emosi dengan kebiasaan

Menyimpan data secara lokal untuk menjaga privasi

2. Tujuan Produk
2.1 Tujuan Utama
Membantu pengguna menyadari dan menginterupsi kebiasaan membuka aplikasi secara otomatis, dengan cara menambahkan jeda reflektif di momen sebelum kebiasaan itu terjadi — bukan dengan memblokir, tapi dengan mengembalikan kendali kepada pengguna.

2.2 Tujuan Spesifik
Menyediakan mekanisme jeda (delay-to-open) sebelum aplikasi target dibuka

Mencatat dan menganalisis pola pemicu pembukaan aplikasi

Memberikan pertanyaan reflektif yang dipersonalisasi berdasarkan pola historis

Menyediakan jurnal wellness yang menghubungkan emosi dengan kebiasaan digital

Menyediakan artikel edukasi pendukung tentang dopamin dan kebiasaan

Menjaga privasi pengguna dengan menyimpan semua data secara lokal

2.3 Metrik Keberhasilan
Metrik	Target

3. Target Pengguna
3.1 Pengguna Utama
Mahasiswa (18–24 tahun) yang merasa sulit lepas dari media sosial

Pekerja muda (25–35 tahun) yang ingin mengurangi doomscrolling

Siapa pun yang menyadari kebiasaan buka HP berlebihan tapi tidak tahu cara menghentikannya

5.11 DAO: GateEventDao
kotlin
@Dao
interface GateEventDao {
    @Insert
    suspend fun insert(event: GateEvent)

    @Query("SELECT * FROM gate_events WHERE timestamp >= :startTime ORDER BY timestamp DESC")
    suspend fun getEventsSince(startTime: Long): List<GateEvent>

    @Query("SELECT COUNT(*) FROM gate_events WHERE action = 'cancelled' AND timestamp >= :startTime")
    suspend fun getCancelledCount(startTime: Long): Int

    @Query("SELECT COUNT(*) FROM gate_events WHERE action = 'opened' AND timestamp >= :startTime")
    suspend fun getOpenedCount(startTime: Long): Int

    @Query("SELECT reason, COUNT(*) as count FROM gate_events WHERE timestamp >= :startTime GROUP BY reason ORDER BY count DESC")
    suspend fun getReasonDistribution(startTime: Long): List<ReasonCount>

    @Query("SELECT strftime('%H', timestamp / 1000, 'unixepoch') as hour, COUNT(*) as count FROM gate_events WHERE timestamp >= :startTime GROUP BY hour ORDER BY hour")
    suspend fun getHourlyDistribution(startTime: Long): List<HourCount>
}

    suspend fun getEmotionDistribution(startTime: Long): List<EmotionCount>
}

9. Keamanan & Privasi
9.1 Prinsip Privasi
Semua data disimpan lokal. Tidak ada server, tidak ada cloud sync.

Data yang dikirim ke AI minimal. Hanya data agregat yang tidak mengidentifikasi user.

User punya kendali penuh. Bisa ekspor dan hapus semua data kapan saja.

Transparan. User tahu data apa yang dibaca dan mengapa.

Jurnal bersifat privat. Isi jurnal tidak pernah dikirim ke AI tanpa izin user.

9.2 Izin yang Diminta
Semua izin diminta dengan penjelasan mengapa diperlukan. User bisa menolak, tapi fitur tertentu tidak akan berfungsi.

11. Risiko & Mitigasi
Risiko	Dampak	Mitigasi
UsageStats delay	Overlay muncul terlambat	Gunakan polling interval pendek; pertimbangkan AccessibilityService sebagai alternatif
Overlay tidak muncul di beberapa perangkat	Fitur inti tidak bekerja	Testing di berbagai merek; fallback ke notifikasi
Gemini API timeout	Overlay kosong	Fallback ke pertanyaan statis
User merasa terganggu	Aplikasi di-uninstall	Desain yang tenang; user bisa atur durasi; tidak memblokir
Data bocor	Kepercayaan hilang	Semua data lokal; tidak ada server
Baterai terkuras	User tidak nyaman	Optimasi foreground service; polling interval efisien
Jurnal terlalu berat	User malas menulis	Prompt dari Gemini yang ringan; entri bisa sangat pendek
